# 厝邊聲援 CityVoice — 給隊友的產品介紹

## 直接傳到群組的版本

大家好，我想提議我們這次黑客松做 **「厝邊聲援 CityVoice」**，一個整合進城市通 TownPass 的**語音優先、多語言市政服務助理**，主題是「數位平權」。

我們主要想幫助不擅長打字或使用複雜 App 的長者、中文行政用語不熟悉的新住民，以及使用舊手機的市民。使用者可以用熟悉的語言說出需求（目標是臺灣華語、台語及越南語；依實測結果逐步開放），確認系統聽到的內容，接著找到有**官方資料來源與更新日期**的服務資訊，並看到容易理解的下一步。

它不只是普通的 AI 聊天室：如果使用者卡住，可以產生**城市接力卡**，把目前任務和下一步安全地分享給親友或真人窗口。接力卡不放證號、密碼、登入資料、完整對話或其他不必要的個資。

AI 的語音辨識和語言理解會優先研究**在手機本機運行、可離線使用**的方案，符合比賽的裝置端 LLM 限制。但我們不會硬塞大模型：即使 AI 不支援或使用較舊手機，也有文字、按鈕和基本服務模式，讓人完成同一件事。

**第一版只做一條真正完成的服務情境**，例如「找人協助使用手機／尋找數位協助資源」：語音或文字輸入 → 確認需求 → 選行政區 → 查看可信的官方資訊 → 取得下一步 → 產生接力卡。台語、越南語語音及本機 LLM 是最優先研究的亮點，但要先通過授權、語言與 iPhone 實機測試，不能只做 PPT 效果。

我們會用 iPhone + Xcode + Flutter 當主要實測平台，保留 Android 驗證；介面會盡量沿用 TownPass / TownPass-Services 和官方設計系統。現在最急的是先把專案跑起來、確認 Flutter/Vue 整合、做離線 STT PoC，並找出合法且有效的臺北市資料。

一句話：**讓每個人不用先學會科技或行政術語，也能用熟悉的方式找到可信的市政協助。**

## 短版（3 句）

「厝邊聲援 CityVoice」是整合進城市通的語音優先、多語言市政服務助理，目標是讓臺灣長者、新住民與舊手機使用者，也能用熟悉的方式取得市政資訊。它用經驗證的本機語音和受控 AI 協助理解需求，提供有官方來源的下一步，遇到困難時可把安全的任務摘要交給親友協助。AI 不可用時仍能切換完整文字／Basic Mode，讓數位平權不只停留在口號。

## 對外產品簡介（較正式）

**產品名稱：**厝邊聲援 CityVoice

**標語：**用你熟悉的語言，找到城市的幫忙。

**主題：**數位平權、無障礙、可信市政資訊、適應不同設備的 AI。

**問題：**數位公共服務常要求使用者知道服務名稱、閱讀大量行政文字、熟悉手機操作和中文輸入。這些門檻對某些長者、新住民及設備受限者並不友善。

**解法：**CityVoice 以語音優先、文字可替代的介面協助使用者描述需求，系統將需求對應到經確認的官方市政資料，拆解成清楚的下一步；需要協助時產生可供親友閱讀的接力卡。支援度以語言、設備、ASR、LLM、TTS 分別實測標示，不將未完成的能力視為已上線。

**核心差異：**

1. 用生活語言理解需求，而非要求使用者知道行政術語。
2. AI 不生成政府規定；行政資訊來自合法、可追溯的官方資料。
3. 不是只有「回答」，而是「確認需求→下一步→真人接力」。
4. 沒有 AI／沒有麥克風／使用舊手機也能完成主流程。

**MVP：**一條可完整展示的數位協助服務流程；本機語音優先驗證華語，再選台語或越南語作為非華語亮點；正式語言支援需視模型授權與真機測試結果決定。

**預期展示：**從 TownPass 進入、說話或輸入、逐字稿確認、選行政區、顯示有來源的結果、閱讀下一步、產生接力卡；示範無模型 Basic Mode 如何保留核心服務。

**邊界：**不是政府官方核准／申請系統、不收集敏感個資、不使用雲端 LLM 進行運行時推論、不承諾所有語言或舊機型立即支援。

## 這週團隊的共同目標

- **Team Lead：**確認主辦規則、賽前程式範圍、工作分工與 Demo 範圍。
- **Flutter／iOS：**iPhone 真機啟動、Flutter↔Vue bridge、離線測試。
- **AI／ML：**真機 ASR 和本機 LLM PoC、語言正確率、效能、模型與權重授權。
- **Vue／UI：**無障礙首頁、文字任務、逐字稿確認、接力卡。
- **Data／QA：**合法的官方開放資料、來源與有效日期、翻譯審核、真機與使用者測試。
