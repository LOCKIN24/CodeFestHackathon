Follow-up: map each view and shared component to its complete data sources, route inputs, empty/error states, live requests and privacy implications. No live submission, payment, phone call, account change or location sharing was attempted.

Scanner source checkpoint: `qr_code_scan_controller.dart` uses `mobile_scanner` and `image_picker`; gallery cancellation or caught errors produce null, which the view treats as failed recognition. Camera and photo permissions and device-specific errors remain unverified. The suspension screen's email link uses `url_launcher`, requires a usable mail application, and displays a toast when it cannot launch; its suspend callback is empty. Account settings navigation calls `syncAccount` after return, while the checked account service uses bundled mock data. Authentication remains unknown.

This batch confirms that profile editing modifies an in-memory account loaded from bundled mock JSON; service pins are an in-memory reactive list, with no persistence in the reviewed controller. The 1999 agreement uses shared preferences and does not itself place the call. Coupon detail reads a Pinia coupon map keyed by route `id`; its reviewed use/store confirmation handlers only change dialog state and do not update the wallet store. Map launch depends on the bridge and has a window-open fallback on a false response. Library book reservation code explicitly labels its data demonstrative and writes records to local storage; a real request is commented out. Direct loading, missing IDs, browser and device behavior remain unverified.

Main-tab coverage review: Home banners and activities come from bundled mock JSON, while images and hosted links depend on network. The checked-out Vue coupon root initializes mock Pinia lists; detail routes depend on store data and IDs. Bill routes use hosted URLs, fee store data, route IDs and a QR bridge where applicable. Host deployment/version, real authentication and payment integration remain unknown. Settings switches have local widget state only in the inspected view; the controller's displayed last-login time is `DateTime.now()`.

Camera, gallery, bridge availability and hosted version remain device/deployment dependencies. Citizen-report search detail requires an `id` in the route but the checked view logs it and renders the same bundled mock detail regardless. Subscription and counter records in the reviewed Vue routes use mock or local data; their source routes are not proof of production integration.

Disaster, citizen and counter roots use bundled mock data; disaster and citizen report handlers inspected here do not establish real submission. Counter map and phone actions use bridge messages. Vue subscription choices use mock JSON or localStorage and a notification bridge; the API example is commented. Flutter subscription display uses a separate in-memory service. Library detail and notice routes require IDs in mock stores; missing IDs and deployed runtime behavior remain unverified.

The fee route audit confirms that the named `/fee-payment` parent has no component or empty-path child. Fee categories, bills and history are initialized from bundled mock JSON. Fee search stores recent terms in localStorage; fee detail and history detail require IDs, and the payment step requires both fee ID and comma-separated bill IDs. Completion UI reads local payment state; the source reviewed here does not establish a real payment.

The final Flutter route review found typed `Get.arguments` contracts for message detail (`MessageItem`), subscription detail (`SubscriptionItem`), activity list (`ActivityList`), activity detail (`ActivityItem`) and basic-info editing (`BasicInfoEditArgument`). Activity callbacks can supply null during loading. The WebView expects an optional `WebViewArgument` object rather than a raw URL string; without a usable URL content is not established. Source's geolocation callback returns an allow response, but actual device/OS permission and runtime behavior are unverified. The 1999 agreement route is conditional on bridge dispatch, telephone-handler availability and stored consent.

The services police card's local-URI host lacks the slash in the registered GetX route when passed to `Get.toNamed`. Source alone has not established successful resolution, so the normal entry remains conditional and requires future runtime verification.
