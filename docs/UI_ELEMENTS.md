## Wider audit queue

[SOURCE_CONTROL_INDEX.md](SOURCE_CONTROL_INDEX.md) records 229 mechanically detected control-handler lines and 44 modal declarations across Flutter page files and Vue views/components. These are candidates, not a verified count of distinct UI elements: generated controls, multi-line handlers, shared components and conditionals require contextual review. The seven syntactically empty callbacks found by this scan are flagged `not_implemented`; other missing, null, TODO or stub callbacks are not exhausted by that count. The index intentionally does not assert an element's destination or that a nonempty callback successfully performs its stated purpose.

## Services, home, and library dialog audit

Services' 有話要說 opens hosted citizen reports and 警政報案 opens the local police page. 市政服務, 城市生活, 防疫醫療 and 市政APP have TODO-only callbacks. Trending items use a model URL; 施工資訊 has an empty URL and `openUri` returns without navigating. The shared pinned-item and add-button implementations use caller-supplied callbacks; their service-tab and editor contexts differ. Home's 市政新聞 callback is empty; 1999 invokes a telephone URL directly. Home subscription controls open hosted pages or pass a `SubscriptionItem` to Flutter detail. No telephone action was performed.

The library picker does not automatically close after selecting a library: it emits the ID to its parent. It loads maps and requests location on mount; the nearby list shows a spinner until the location callbacks mark the map ready. A failed map loader is not handled in this component. The limit dialog checks the current selected-series count rather than summing existing reservations. Reservation success and failure are based on demonstration local state; the success screen does not prove a live reservation. See `SCREEN_STATE_REGISTRY.json` and `UI_CONTROL_REGISTRY.json` for conditions, actions and evidence.

Subscription cards expand locally; their subscribe and unsubscribe controls toggle the item, store the list in localStorage, and post a notification bridge message. The API example is commented. Fee and ticket payment method buttons set local store fields and open confirmation dialogs; the reviewed confirmation handlers route to completion screens, without establishing a payment. Fee and library keyword search keep separate localStorage histories.
