# Known issues and verification record

Checked 2026-10-29 on this Mac; see SETUP.md for versions and repository commits.

- **Xcode 27 Device Hub:** `open -a Simulator` fails because this Xcode version uses Device Hub in place of the standalone Simulator app. Open Xcode > Open Developer Tool > Device Hub, then select iPhone 17 Pro. The pinned Flutter debug app was visually verified on iOS 26.5: Home, Services, Bills and Perks tabs switched successfully and the hosted perks page rendered. The first-run notification request was declined on this simulator, so notification delivery was not tested. The previous claim that Xcode needed repair was incorrect.
- **Physical iPhone unverified:** Xcode's device list showed an iPhone 12 Pro Max as unavailable; no installation or run was attempted. Connect/unlock/trust it and enable Developer Mode, then configure signing as in SETUP.md. A physical iPad also appeared unavailable.
- **Vue dependency install:** pnpm 12.14.0 returned `ERR_PNPM_IGNORED_BUILDS` for esbuild and vue-demi. The frozen lockfile install succeeded with pnpm 9.15.9 as documented, including their postinstall scripts. No dependency upgrade was made.
- **Google Maps:** the local library page showed the Google Maps key/billing error; `src/stores/googleMaps.ts` has an empty API key. A suitably restricted authorized key and enabled API/billing are needed to test maps; do not commit it. External map and location services remain unverified.
- **Flutter warnings:** the debug log printed `unhandled element <style/>; Picture key: Svg loader`. Its visual impact is unverified. Flutter also warned that `flutter_inappwebview_ios` lacks Swift Package Manager support and fell back to CocoaPods. No dependency changes were made.
- **Vue build warnings:** production build/type-check succeeded with an outdated Browserslist data warning and a large JavaScript chunk warning; `vue-tsc` also printed `languageId not found ... App.vue` / `!!sourceScript` despite exit 0. No upgrades or optimizations were applied.
- **Coverage:** browser rendering confirmed `/`, `/citizen-report/`, `/library-service/` and navigation from the library to keyword search. It does not verify every page, submissions, external APIs, physical device, or bridge. The local service is not connected to Flutter by default. Many values and transactions are examples.
- **CocoaPods lock drift:** automatic pod install changed the CocoaPods version and inappwebview checksum in `ios/Podfile.lock`; the generated diff was restored after the successful build, leaving the repository clean. Other CocoaPods versions may produce similar local drift; review before committing.
- **Security review before extension:** the WebView message dispatcher handles origin/frame metadata without checking it and supports sensitive native actions. The existing design needs an origin, frame and payload review before new privileged handlers or untrusted pages are added.
